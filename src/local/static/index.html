★ Stage Details
1 DISCOVER Vulnerability Agent

Queries Red Hat Insights for CVE details (CVSS score, affected packages, errata) and identifies all systems in your inventory affected by this vulnerability.

Backend
INSIGHTS_MCP_ENDPOINT — MCP server connecting to Red Hat Insights API
Fallback
Demo hosts with pre-configured system profiles when Insights is unavailable
2 PREDICT Risk Agent

Invokes a machine learning model to calculate a composite risk score (0–100) per host based on CVSS severity, host age, fleet size, workload type, and historical patch success. Classifies hosts as ok (auto-patch) or review (needs human approval).

Backend
RISK_URL — RHOAI model serving endpoint on OpenShift
Key Metrics
Failure probability, impact probability, risk classification (LOW / MEDIUM / HIGH)
3 REASON Risk Agent + Automation Agent

The Risk Agent uses RAG to search a vector database of historical patch records, finding similar past patches and failure patterns. The Automation Agent then produces a risk-aware phased deployment strategy (Test → Canary → Production).

Backend
LLAMA_STACK_URL + VECTOR_DB_ID for RAG lookups
Outputs
Patch history analysis, host-level decision support, phased deployment strategy
4 EXECUTE Automation + Diagnosis Agents

The Automation Agent invokes Ansible Lightspeed to generate a remediation playbook, publishes it to GitHub, syncs the AAP project, creates job and workflow templates, and launches the workflow with an approval gate. After human approval, executes in three phases with automatic failure detection and rollback. On failure, the Diagnosis Agent performs LLM-powered root cause analysis via RAG and proposes remediation.

Backend
AAP_BASE_URL + AAP_TOKEN, GITHUB_TOKEN
Phases
Test systems → Production canaries → Remaining production
5 LEARN Learning Agent

Records the outcome of every host patch (success, failure, rollback, remediation) as training events. Updates the RAG vector store for future REASON queries. Feeds a data pipeline that drives continuous model improvement.

Data Pipeline
Patch outcomes flow through ETL into a Feature Store with structured ML training features
Model Retrain
OpenShift AI retrains the risk model, stores it in Model Registry, deploys via KServe to replace the PREDICT endpoint
Feedback Loop
Each patch cycle makes future risk predictions more accurate
$ ROI ROI Agent

Calculates the financial value created by the patch run. Compares manual vs. AI-assisted effort across four economic dimensions: engineering effort avoided, reduced exposure window, automation reuse, and faster recovery. All calculations use configurable assumptions and reference published industry benchmarks.

Dimensions
Engineering effort, reduced exposure, automation reuse, faster recovery — with animated value bars
Benchmarks
Forrester TEI, Red Hat/Principled Technologies, IDC, ABB case study — each cited with source
Time Machine
Side-by-side timeline comparing manual (full day) vs. AI-assisted (25 minutes) remediation
Transparency
Configurable labor rate, per-host costs, and explicit assumptions disclaimer

► Demo Talk Track

A scene-by-scene guide for presenting AIP. Each scene maps to what you'll see on screen. Read the Say sections aloud; the Watch for notes tell you what to point at. Timing is automatic — just talk along with the flow.

★ Opening — Set the Stage ~30s · before starting
“Imagine a critical CVE drops. Today that means tickets, war rooms, and weeks of manual patching. What if six AI agents could take it from discovery to fully patched — with a human in the loop only when it matters?”
Do: Point to the pipeline bar at the top — explain the five stages: Discover → Predict → Reason → Execute → Learn. Mention the A2A sidebar will show agent-to-agent messages in real time.
1 DISCOVER — CVE Intake ~20s
Do: Enter a CVE ID and click Start Patch Flow.
Watch for: Pipeline stage 1 lights up red. A2A sidebar shows Console → Patch Manager → Vulnerability Agent message chain.
“The Vulnerability Agent queries Red Hat Insights via an MCP server. It pulls CVE details — CVSS score, affected packages, errata — and identifies every system in our fleet that's exposed. No one opened a spreadsheet.”
2 PREDICT — Risk Scoring ~25s
Watch for: Stage 2 lights up amber. Host cards appear with risk scores and ok/review badges. The status bar shows the risk model being invoked.
“Now the Risk Agent calls a machine learning model running on OpenShift AI. It scores every host — factoring in CVSS severity, system age, workload type, and historical patch outcomes. High-risk hosts get flagged for human review; safe ones go straight to auto-patch. This is data-driven triage, not gut feel.”
Tip: Click a host card to show the risk breakdown. Point out the ok vs. review classification.
3 REASON — LLM Analysis & Strategy ~30s
Watch for: Stage 3 lights up blue. History analysis panel appears. Phased strategy (Test → Canary → Production) is generated.
“Here's where the LLM earns its keep. The Risk Agent uses RAG — Retrieval-Augmented Generation — to search a vector database of every patch we've ever run. It finds that similar patches failed on Fridays and had drain timeout issues. Then the Automation Agent uses that intelligence to build a phased deployment strategy: test first, then canaries, then production. The AI isn't just predicting — it's reasoning from your own operational history.”
Tip: Good moment to explain RAG for non-technical audiences: “Think of it as the AI searching its memory of every patch you've ever done.”
4 EXECUTE — Playbook & Approval Gate ~30s
Watch for: Stage 4 lights up purple. A2A messages show playbook generation, GitHub publish, AAP template creation. The Approve button appears.
“The Automation Agent calls Ansible Lightspeed to generate a remediation playbook — and it's already learned from that drain timeout issue, so it bakes in a 120-second drain. The playbook goes to GitHub, syncs into AAP, and creates a workflow template with a human approval gate. The system did all the prep; now it pauses and asks a human: are we good to go?”
Do: Pause here. Let the audience absorb the approval gate. This is your “human in the loop” moment.
5 EXECUTE — Phased Rollout ~30s
Do: Click Approve.
Watch for: Three-phase execution progress (Test → Canary → Production). Progress bars fill in real time.
“After approval, execution is fully automated and phased. Test systems go first — if they pass, canary production nodes are next, then the full fleet. At every phase boundary, health checks run before proceeding. If anything fails, the system stops automatically.”
6 SELF-HEAL — Failure, Diagnosis & Remediation ~45s · key moment
Watch for: A host fails its health check. Alert appears. Automatic rollback runs. Diagnosis Agent searches RAG for similar failures. Remediation is proposed and auto-approved.
“This is the highlight. A production host fails its post-patch health check. Watch what happens: the Automation Agent immediately rolls it back — the app is healthy again in seconds. Then the Diagnosis Agent kicks in. It uses the LLM with RAG to search historical failures, finds that this exact pattern happened before with an insufficient drain timeout, and proposes a fix: increase the timeout from 30 to 120 seconds. The fix is applied, the host is re-patched, and this time it succeeds. No pages. No war room. The AI diagnosed and fixed the problem from its own operational memory.”
Tip: This is your strongest demo moment. Slow down here. Let the audience see the failure alert, the rollback, the diagnosis, and the successful retry. The story is: the AI doesn't just patch — it learns and adapts when things go wrong.
7 LEARN — Continuous Improvement ~25s
Watch for: Stage 5 lights up green. Final summary appears with training records generated. A2A shows Learning Agent updating the model.
“Every outcome — success, failure, rollback, remediation — becomes training data. The Learning Agent captures it all and feeds it into a data pipeline: outcomes go to a Feature Store, OpenShift AI retrains the risk model, the new model lands in Model Registry, and KServe deploys it to replace the prediction endpoint. Next time a similar CVE hits, the PREDICT stage is smarter. The system literally gets better at patching every time it patches.”
8a ROI — Hero Banner ~20s
Watch for: ROI pipeline stage ($) lights up green. A dark green hero banner appears at the top with a large dollar figure, plus four stat chips: cost reduction %, hours saved, systems count, and cost-per-host comparison.
“Now let's talk about the money. The ROI Agent just calculated what this single patch run was worth. That headline number is the total labor value created — computed from your engineer labor rate times the hours recovered. The four chips below break it down: we cut cost per system from $36 to $6 — that's a 83% reduction. And we saved over 15 hours of engineering time across these systems. All of these numbers come from configurable assumptions you can tune in Settings.”

? Common Questions
What if we don't have all the backends configured?
Every stage tries real APIs first and falls back to built-in demo data with clear logging. You can demo with zero backends, one backend, or all of them — the flow works the same.
Where does the LLM run?
Llama Stack on OpenShift, using a locally-hosted Llama model. No data leaves your infrastructure. RAG queries hit a Milvus vector database for historical patch records.
Is the human always in the loop?
Yes, at the approval gate before execution begins. The system does all the analysis and preparation autonomously, then pauses for human judgment. Post-approval, rollback and remediation are automatic to minimize MTTR.
How does it learn?
Patch outcomes feed a data pipeline → Feature Store → OpenShift AI → Model Registry → KServe. The retrained model replaces the PREDICT endpoint, so risk scores improve continuously.
What Red Hat products are involved?
Red Hat Insights (CVE data), Ansible Automation Platform (execution), Ansible Lightspeed (playbook generation), OpenShift AI (model training & serving), and Llama Stack on OpenShift (LLM reasoning).
