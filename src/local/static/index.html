★ Stage Details
1 DISCOVER Discovery Agent

Queries Red Hat Insights for CVE details (CVSS score, affected packages, errata) and identifies all systems in your inventory affected by this vulnerability.

Backend
INSIGHTS_MCP_ENDPOINT — MCP server connecting to Red Hat Insights API
Fallback
37 demo hosts with pre-configured system profiles when Insights is unavailable
2 PREDICT Risk Agent

Invokes a machine learning model to calculate a composite risk score (0–100) per host based on CVSS severity, host age, fleet size, workload type, and historical patch success. Classifies hosts as ok (auto-patch) or review (needs human approval).

Backend
RISK_URL — RHOAI model serving endpoint on OpenShift
Key Metrics
Failure probability, impact probability, risk classification (LOW / MEDIUM / HIGH)
3 REASON Reason Agent

Uses RAG to search a vector database of historical patch records. Finds similar past patches, identifies patterns, generates per-host recommendations (Why? analysis), and produces a risk-aware phased strategy. Also invokes Ansible Lightspeed to generate specialized playbooks.

Backend
LLAMA_STACK_URL + VECTOR_DB_ID for RAG lookups
Outputs
Patch history analysis, host-level decision support, phased deployment strategy
4 EXECUTE Automation Agent

Publishes the generated playbook to GitHub, syncs the AAP project, creates job and workflow templates, and launches the workflow with an approval gate. After human approval, executes in three phases with automatic failure detection, rollback, root cause analysis, and AI-driven remediation.

Backend
AAP_BASE_URL + AAP_TOKEN, GITHUB_TOKEN
Phases
Test systems → Production canaries → Remaining production
5 LEARN Learning Agent

Records the outcome of every host patch (success, failure, rollback, remediation) as training events. Updates the RAG vector store so future REASON queries can reference this patch. Generates model retraining data to improve PREDICT accuracy over time.

Feedback Loop
Each patch operation makes the system smarter for the next CVE
Storage
Vector store for RAG, training records for model retraining
⇄ Unified Mode

Every stage tries real APIs first, then falls back gracefully.

LIVE Real backend responded — using production data
FALLBACK Backend unavailable — using built-in demo data with FIX hints
Check the Server Log tab for per-stage LIVE/FALLBACK status. Configure backends in Settings.
